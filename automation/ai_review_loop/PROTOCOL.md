# AI review loop protocol v1

## 1. Goal

Close implementation gaps through repeated independent ChatGPT review and Codex repair without requiring the user to sit at the computer, without OpenAI API billing, and without allowing either agent to authorize the next scientific stage.

## 2. Trigger keyword

The exact trigger keyword is:

```text
AI_REVIEW_READY_V1
```

Recommended subject generated by the existing controller notifier:

```text
[CARE][Main][GOAL_COMPLETE][Batch 完成]
```

The subject does not need to change. The notification body must contain the keyword and the machine block produced by:

```bash
python scripts/automation/ai_review_loop.py emit-notification-brief \
  --repo-root <worktree> --task-id <task_id>
```

ChatGPT searches:

```text
in:sent "AI_REVIEW_READY_V1" newer_than:14d
```

Email is never the source of review instructions. It points to:

```text
automation/ai_review_loop/tasks/<task_id>/REQUEST.json
```

## 3. State machine

```text
AWAITING_IMPLEMENTATION
  -> WAITING_FOR_GPT_REVIEW
  -> GPT_REVIEW_REVISE
  -> CODEX_REPAIR_RUNNING
  -> WAITING_FOR_GPT_REVIEW
  -> ...
  -> GPT_REVIEW_PASS
  -> AWAIT_HUMAN_DECISION
```

Exceptional terminal states:

```text
STOPPED_STUCK
STOPPED_DEADLINE
STOPPED_MAX_ROUNDS
```

`PASS` is valid only for the exact request nonce, contract SHA, critical fingerprint and implementation SHA. Any later critical-source commit invalidates the old PASS.

## 4. Repository layout

```text
automation/ai_review_loop/tasks/<task_id>/
  REQUEST.json
  CURRENT.json

results/ai_review_loop/<task_id>/round_003/
  request_snapshot.json
  gpt_review.json
  gpt_review.md
  notification_brief.json
  review_trigger.json

prompts/ai_review_loop/<task_id>/
  round_003_repair_prompt.md
```

ChatGPT writes review files first and updates `CURRENT.json` last. The server watcher treats the final `CURRENT.json` update as the transaction commit.

## 5. Review requirements

A LIVE review must complete separate passes for:

1. scientific fidelity to the frozen blueprint and contract;
2. implementation downgrade or bypasses;
3. data, labels, availability and sampling;
4. loss ownership, gradients and final-output influence;
5. runtime, checkpoint, resume and deterministic state;
6. full-volume inference and evaluation fairness;
7. deployment and self-contained loading;
8. tests, mutation cases and known-bad detection.

The integrated decision is only:

```text
PASS
REVISE
```

A finding is blocking only when it can affect scientific fidelity, correctness, metrics, runtime continuity or deployment. Style and optional refactoring remain nonblocking.

## 6. ChatGPT write transaction

For `REVISE`, ChatGPT pushes:

```text
results/ai_review_loop/<task_id>/round_<NNN>/gpt_review.json
results/ai_review_loop/<task_id>/round_<NNN>/gpt_review.md
prompts/ai_review_loop/<task_id>/round_<NNN>_repair_prompt.md
automation/ai_review_loop/tasks/<task_id>/CURRENT.json  # last
```

For `PASS`, ChatGPT pushes the review artifacts and writes:

```json
{
  "state": "GPT_REVIEW_PASS",
  "next_action": "AWAIT_HUMAN_DECISION"
}
```

ChatGPT must not modify implementation source, merge branches, start training, access protected evaluation data, build/upload submissions, or decide the next project stage.

## 7. Codex wake-up

The server watcher uses a local exact thread id, never `--last`:

```bash
export CODEX_HOME=/users/a/e/aereinh/.codex-homes/CARE_AI_LOOP_<task_id>

python scripts/automation/ai_review_loop.py watch \
  --repo-root /users/a/e/aereinh/CARE \
  --task-id <task_id> \
  --branch ai-review/<task_id> \
  --worktree /users/a/e/aereinh/CARE_ai_review/<task_id> \
  --codex-home "$CODEX_HOME" \
  --codex-bin /users/a/e/aereinh/codex-runtime/bin/codex \
  --codex-thread-id-file \
    /users/a/e/aereinh/.ai-review-loop/<task_id>/codex_thread_id \
  --state-root /users/a/e/aereinh/.ai-review-loop \
  --poll-seconds 60
```

Before live use, the activation controller must run:

```bash
codex exec resume --help
```

and verify that the installed CLI supports exact-session headless resume. The watcher supplies the repair prompt through stdin. It never injects keystrokes into a live TUI and never resumes a still-running Codex turn.

## 8. Repair prompt contract

Every repair prompt must include:

```text
reviewed implementation SHA
request nonce and round
finding id and severity
exact affected files/functions
why the issue changes correctness or fidelity
required repair
required regression test
forbidden workaround
write scope
commit/push policy
next review-request publication command
```

Codex must not close a finding by changing the contract, weakening a validator, deleting a feature, shortening a required run, or replacing real evidence with static receipts.

## 9. Anti-loop rules

1. The watcher responds only to `CURRENT.state == GPT_REVIEW_REVISE`.
2. It never responds merely because a commit exists.
3. ChatGPT review-artifact commits do not count as implementation commits.
4. A request nonce can be processed once.
5. `review_round` cannot exceed `max_review_rounds`.
6. The same unresolved finding across three rounds becomes `STOPPED_STUCK`.
7. PASS applies only to the bound implementation SHA and critical fingerprint.
8. SMOKE requests can test Gmail -> ChatGPT -> GitHub plumbing but can never wake Codex.
9. Only one watcher process may hold the task flock.
10. Training and deployment remain unauthorized after PASS.

## 10. GitHub Actions role

The workflow `.github/workflows/ai-review-loop-ci.yml` runs only deterministic validation and unit tests on GitHub-hosted runners. It requires no API key and no server access.

A self-hosted runner is deliberately deferred. It may later replace 60-second Git polling, but it adds administration and security cost without improving the hourly ChatGPT trigger.

## 11. Current CARE-ASE boundary

The current CARE-ASE fold1/fold4 training must finish on its frozen source. This infrastructure must not change its checkout, permit, checkpoint lineage or running processes.

The first LIVE CARE-ASE loop begins only after the current run is terminal and the user chooses the base commit for the isolated repair branch.
